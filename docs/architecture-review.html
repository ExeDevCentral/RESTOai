1. Desacoplar el "God Server" (1280 líneas) en Módulos de Dominio

Strong (Urgente) ports & adapters
Archivos involucrados: server/index.js • server/db.js • packages/db/src/client.ts
❌ Antes: Monolito Superficial y Fricción
graph TD Client[Cliente / POS / KDS] --> Server[server/index.js (1280 líneas)] Server -->|Lectura Cruda| JSON[(server/data.json)] Server -->|Import Dinámico Aislado| Domain[packages/domain] Server -->|Sin Conectar| Drizzle[(packages/db Drizzle Engine)]

Un único archivo responde HTTP, calcula stock, genera CAE fiscal, emite ESC/POS y guarda en JSON.

✅ Después: Módulos Profundos y Rutas Limpias
graph TD Client[Cliente / POS / KDS] --> App[server/app.js] App --> R_Orders[routes/orders.js] App --> R_Kitchen[routes/kitchen.js] App --> R_Cash[routes/cash.js] R_Orders --> KobeDomain[packages/domain] R_Orders --> KobeDB[packages/db Drizzle Repositories]

Rutas delgadas con un adaptador de persistencia real conectado a Drizzle / PostgreSQL.

Problema: Cualquier cambio a la lógica fiscal o de comandas requiere editar el mismo archivo monolítico.
Solución: Extraer routers Express por dominio (Orders, Cash, Inventory, Fiscal) delegando en `@kobe/db`.
Beneficios:
  • Mayor localidad de código
  • Tests unitarios de API aislados
  • Elimina mutaciones concurrentes a data.json

2. Modularizar el Frontend PWA (app.js de 2448 líneas)

Strong (Urgente) in-process
Archivos involucrados: public/app.js • public/modules/*
❌ Antes: Estado Global y Script Monolítico
graph TD AppJS["public/app.js (2448 líneas)"] AppJS --> POS["renderTables() & Modal"] AppJS --> KDS["renderKDS() & Timers"] AppJS --> Offline["OfflineQueue & Eventos"] AppJS --> Cash["CashRegister & Arqueos"] AppJS --> Print["ThermalPrinter & QR"]

Colisiones de variables globales, render functions mezcladas y dificultad de mantenimiento.

✅ Después: Vistas Modulares Desacopladas
graph TD Main[public/main.js Entrypoint] Main --> Mod_POS[modules/posView.js] Main --> Mod_KDS[modules/kdsView.js] Main --> Mod_Queue[modules/offlineQueue.js] Main --> Mod_Cash[modules/cashView.js] Main --> Mod_Print[modules/printView.js]

Módulos ESM independientes con responsabilidades claras y eventos limpios.

Problema: Dificultad de navegación y riesgo de efectos colaterales al modificar la UI.
Solución: Descomponer `public/app.js` en módulos ESM (`type="module"`).
Beneficios:
  • Cero colisiones globales
  • Fácil debugging por pantalla
  • Carga limpia y mantenible

🌟 Recomendación Prioritaria: Candidato 1 & Candidato 2

Para que el sistema deje de hacer agua y esté verdaderamente listo para producción, la prioridad absoluta es desacoplar el backend y el frontend en módulos limpios. Con el dominio (@kobe/domain) y la base de datos relacional (@kobe/db) ya blindados con 63 tests pasando, esta refactorización le dará al proyecto una solidez industrial inquebrantable.
